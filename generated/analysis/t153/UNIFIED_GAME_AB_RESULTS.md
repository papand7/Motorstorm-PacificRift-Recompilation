## 4. Comparisons

1. **Baseline vs the performance preset (A → P): +13 % FPS (6.41 → 7.27), VERIFIED.**
   - The RSX drain falls 127 → 20 ms, mostly vertex expansion (121 → 16), and the PPU's ref throttle wait falls 60 → 31 ms.
   - The frame thread then reaches frame end sooner and spins longer at `0x50C818` (17.6 → 30.8 ms), so its running time rises 45 → 64 ms. The saved RSX time moves into the Wws wait rather than all becoming FPS.
2. **Integration exe with every switch off (Z) = baseline:** 6.50 vs 6.41, inside A's own range. No hidden default change.
3. **Snapshot optimizations:**
   - In hash-only mode (Z), snapshots cost 36 ms/frame and about 1.2 GB hashed per frame.
   - The preset's epoch already removes almost all of this: C, which runs the epoch without write-watch, costs 0.6 ms (11 MB).
   - Write-watch (B, D, E) takes it to 0.2 ms/frame with no hashing: a 0.4 ms saving.
   - **B vs P: 7.27 vs 7.27, no measurable FPS change.** Correct and harmless, but not a gain on this route.
4. **Fast vertex fetch (with the kick, arm C):** no gain. C is 7.13 vs P 7.27, and expansion is 18.9 vs 16.4 ms; Cr2 alone (15.9) equals P. With compact records, expansion in game is already about 16 ms, and the synthetic 35 % draw-callback saving does not appear. Two runs cannot separate this small negative from noise: HYPOTHESIS, not a regression finding.
5. **Frame-clock kick:** C does not isolate it from fast fetch. Its target, RSX idle (`other`), is 57–63 ms in every preset arm, and the GPU fence wait is 0 everywhere. No measurable effect on this route.
6. **Indirect-call fast path (E vs D):** 7.17 vs 7.20; frame-thread running 63.7 vs 64.6 ms; spin 30.8 vs 30.7. No measurable effect. The 9 ns/call micro-bench saving is below the noise of a 124 ms frame.
7. **Combined (D, E):** 7.20 and 7.17, the same as P within run spread. T150, T151 and T152 together add nothing measurable over the T122/T149 preset.

**Wws completion spin (the T152 question):** no integrated optimization reduces it.
- It is 30.5–31.1 ms in every preset arm (B–E) vs 30.7–30.8 in P, and 33.7 ms in T149 P1 on a different exe.
- Wws AOT is not present in any launched exe, so none of this can be attributed to it.

## 6. Limits and next optimization

**Fastest verified configuration:** the T122/T149 preset. **P (T146 exe) and B (integration exe + write-watch) tie at 7.27 FPS**, and B has no observed correctness regression.
- Leave the T150, T151 and T152 switches opt-in: they are correct but measurably neutral in game.
- No default change is justified by these runs.

**New limiting stage: the PPU frame thread, gated by SPU Wws job completion.**
- The critical path is "running" (PPU frame thread) in about 75–85 % of frames in every preset arm.
- Of its about 64 ms running time, about 30.7 ms is the busy-spin at `0x50C818` on the Wws job counters.
- Its other waits are the ref throttle `0x72E1E0` (about 31 ms) and the Havok wait `0x30B710` (17.5 ms in every arm, unchanged by any switch).
- The RSX thread is idle about 60 ms of each frame and the GPU fence wait is 0, so neither the RSX CPU nor the GPU limits the frame.

**Proposed next task:** integrate T152's Wws AOT build option (root `9cd7ef2`, `MSPR_WWS_AOT=ON`) into a T153 port copy, verify it offline, and request a 2-arm × 2-run A/B: B vs B + `PS3_SPU_WWS_AOT=1`, watching `0x50C818`, NOSYS and AOT refusals.
- T106 measured that spin falling 12.5 → 0.3 ms on an older runtime; that result is not yet verified in this runtime.
