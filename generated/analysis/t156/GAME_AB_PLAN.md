- light = race frames 40–499;

`[rsx-hb] frames=` counts RSX passes, not guest frames, and is not used.

## 4. Decision rules

- **P is better than S** only if its mean light-scene Havok wait is lower by more than twice the S-to-S spread (T154: 0.3 ms).
  - Expected from the offline model: 0.3–0.45 ms less chain time (HYPOTHESIS).
  - If kind 38 shows a large in-game thread-creation cost, the gain can be up to about 2 ms.
- **Correctness gates for P** (any failure rejects it):
  - draw and vertex counts per race frame match S at least as well as S matches S;
  - same number of task runs per chain (15 for waves 1–3, plus 10 for wave 4);
  - no crash, hang or new error line;
  - frame dumps show the same sequence.
- **Proposal C goes ahead** if arm D shows that MFC/atomic time is a minority of the 8 ms entries. Otherwise the lock-line path comes first.
- **No claim of an FPS change** from offline numbers. Only the authorised runs decide.

## 5. Bounds

- At most 5 launches (S, P, S, P, D), plus 2 for C, only if separately authorised.
- Each launch stops at race entry + 90 s, with a hard kill at 440 s.
- No change to physics, timestep or guest code. Every arm runs the same lifted Havok images; P changes only which host thread runs them.
