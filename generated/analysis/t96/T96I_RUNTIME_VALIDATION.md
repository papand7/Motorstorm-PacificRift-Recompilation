## Performance
- **First race frame:** about 1.8 s of render passes (338.7 + 1,475.2 ms). Almost all of it is in `record`; `gpu-drain` is 0 and there is no growth or copy.
  - **HYPOTHESIS:** the 1.47 s is first-use shader/PSO creation for race materials. The `record` phase is not subdivided, so this cannot be confirmed.
  - That pass caused GCM `[stall] #1` (walker idle 1 s while the present thread was in `record`).
- **Steady state:** guest ref waits were 0 ms, with about 200 ms per guest frame (about 5 fps) in the last second. The pacing is therefore no longer set by the renderer.
- **Not attributed (HYPOTHESIS: PPU/SPU side):** long syscalls `0x5C`/`0x6B` (1.2–1.7 s), which coincide with the first two frames.
- **No watchdog reports:** `[fc-watchdog]` printed only its start line, so no stall lasted 2 s or more.
- No FPS claim beyond these four seconds.

## Remaining blockers
1. **Observation window (BLOCKED):** race entry at about 200 s leaves about 4 s before the 205 s cap. No race image exists and stability is untested.
2. **First-use `record` cost** of about 1.5 s in the first race frame (cause is a HYPOTHESIS).
3. **`position_attrib_disabled` drops** (806, offscreen, non-display): a separate, older rejection path. Its visual effect is unknown.
